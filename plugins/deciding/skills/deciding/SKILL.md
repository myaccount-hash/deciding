# deciding

## このスキルの目的
ルールに書いていない場面では，この目的に沿って判断する．

- ユーザーが本当に実現したいことを中心に，ユーザーの判断を確定させ，判断リストに残す．
    - 判断には，実現すべき機能（要件）も実装レベルのものも含めてよい．どこまで含めるかは，その都度決める．
- 判断リストは，AIが実行環境と合わせて読めば成果物を作れる指示として書く．
    - 実行環境は，作業時点の既存コードベース，外部情報，AIの実行環境を指す．
    - 同じ判断リストを何度実行しても，記録した判断はいつも満たされるようにする．成果物そのものが毎回同じになることは求めない．
    - 実行環境の内容は書き写さない．判断の中で実行環境に言及するのはかまわない．
    - 記録にない選択は，AIが自由に判断したものとみなす．
- 記録に残るのは，ユーザーが見て決めた判断だけ．
    - 理解するかどうかは，ユーザーに任せる．AIは，理由・代替・質問への答えのように，理解するための材料を出す．
    - ユーザーは，理解するまで質問を重ねてよい．
- 判断負荷を下げる．
    - 下げるのは，1つの判断にかかる手間に限る．判断の数を減らしたり，判断をAIに任せたりはしない．
- ユーザーは，まとまっていない考えのまま投げてよい．
    - AIはそれをカード（推奨・理由・代替）に整え，「こういうことか」と返す．ユーザーはそれを見て確定させる．
- カードごとに議論を並列で進める．
    - 1枚のカードの議論は，他のカードが`OK`になるのを待たずに，ラウンドごとに進める．
- AIはユーザーの指示に従うだけの役ではなく，議論の相手として，自分の推奨と反論を出す．
    - 決めるのはユーザー，論じるのはユーザーとAIの両方．

## カード
AIはユーザーへの質問を1枚ずつカードとして出す．問いが質問に，推奨がAIの仮の答えにあたる．答えが`OK`になったカードの推奨が判断になる．記録したかどうかは，「記録済みの判断」のように修飾して言い分ける．

- ラウンド: AIがカードを出してから，ユーザーが返答するまで．
- ラウンドループ: すべてのカードが`OK`になるか，ユーザーが`RUN`を指示するまで，ラウンドを繰り返すこと．

## 指示
- `DEAL`: カードを出し，ラウンドループを始める．
- `SAVE`: 判断リストに記録する．
- `RUN`: 成果物を作る．
- 英大文字の語は，それだけで書かれたときに限って指示とみなす．「記録して」のように明示的に頼む文も，同じ指示として受ける．
    - 理由: 「テストをrunする」のようなふつうの文で，誤って成果物を作りはじめないため．
- これらの指示がなければ，判断が必要な場面でも自発的にカードを出さない．

## カードの中身
- 前提の欄は設けない．ユーザーに見せる情報は，すべてカードの欄に書く．
- 外部の制約（既存コード，連携先など）はカードにしない．AIが実行環境から読み取る．制約への対応をユーザーが選ぶ場合だけ，カードにする．
- AIに当てがない質問では，推奨に「当てがない」と書き，代替に考えられる答えの候補を並べる．
- 1枚で1つのことだけを問う．推奨の中に，片方だけに賛成・反対できる部分が2つ以上あれば，1枚に複数のことが入っているとみなして分ける．
- 依存する下位のカードは，上位と同時に出す．上位が，同時に出したときの推奨と違う内容で`OK`になったら，下位を作り直して出し直す．下位に出ていた`OK`は無効にする．
- 読み込んだ判断リストの判断や，セッション中に`OK`になった判断と同じこと，またはそこから導けることは，カードにしない．ユーザーの提案がそうしたものであれば，どの判断から導けるかを理由に書いて反論する．
- 理由に，他の判断と矛盾しないことを示すだけの項目を書かない．
- 判断リストと実行環境の食い違いや，判断リストの判断どうしの食い違いに気づいたら，常にその時点でカードとして出す．
    - 記録済みの判断を変えなければ解消しない場合は，そのカードでは判断を変えず，先に判断リストの改善を行うよう勧める．
    - 外部の変化を前もって追う仕組みは設けない．

## カードの書き方
- カードには，`D1`，`D2`のような番号を，ラウンドごとに1から振り直して付ける．`#`は付けない．
    - この番号は，返答でカードを指すためだけに使う．依存関係や，同じラウンドの他のカードを指すときも，この番号を使う．
    - ラウンドをまたいで同じカードかどうかは扱わない．
- 問いは見出しに書く．決まった欄（推奨・理由・代替）だけをラベル付きで書く．それ以外の補いは，ラベルなしの箇条書きで自由に書ける．
- ラベル付きの欄は，内容が1つならラベルと同じ行に書き，複数あるならラベルの下に入れ子の箇条書きで並べる．入れ子の項目はその欄の一部で，`OK`は入れ子の項目にも及ぶ．
- 長さの目安は，推奨は3文まで，理由は3項目まで．超えそうなときは，まず分けられないかを確かめる．それでも超える場合は，そのまま出してよい．
    - 理由: 上限を絶対にすると，分けられない判断の理由が`OK`されないまま削られる．
- 判断リストの判断を指すときは，問いにIDと内容の1行を併記する．まだ記録していない判断は，内容で指す．

```
## D1: <問い>
- 推奨: ...
- 理由:
    - ...
    - ...
- 代替: ...
```

## ラウンドの出力
- 通常のテキストで出力する．選択肢UIは使わない．
- `OPEN`のカードは，毎ラウンド，推奨・理由・代替を付けてすべて出す．前のラウンドから変わっていないカードも省かない．
- 1ラウンドに出すカードの枚数に上限を設けない．
- カードの外には，今回`OK`になった判断の一覧と，返答のお願いのような進行のための文だけを書く．
    - 一覧には，コメントの解釈を確かめられるよう，`OK`になった内容を1行ずつ書く．
- 質問への答えや説明は，関係するカードの理由か，ラベルなしの箇条書きに書く．関係するカードがなければ，新しいカードにする．
- すべてのカードが`OK`になったら，一覧を出して止まる．記録していない判断があれば，一覧の最後に「未記録」と1行添える．ユーザーの指示があるまで作業に進まない．

```
## 今回OKになった判断
- ...

## D1: <問い>
- 推奨: ...
- 理由: ...
- 代替: ...
```

## 返答の処理
- ユーザーは，カードの番号を添えて返答する．番号のない`OK`や`SKIP`だけの返答は，そのラウンドのすべてのカードへの返答とみなす．

```
D1 OK
D2 SKIP
D3 〜のほうがよいのでは
```

- 返答は`OK`・`SKIP`・コメントの3つだけ．
    - `OK`: 推奨で確定する．`OK`は，カードに書いた推奨と理由の両方に及ぶ．
    - `SKIP`: そのラウンドでは判断しない．カードは`OPEN`のまま残る．返答のないカードも`SKIP`と同じに扱う．
    - それ以外の返答は，`NG`や「いいよ」も含めて，すべてコメントとして扱う．
- コメントを受けたら，修正の指示でも新しい提案でも，AIが独立に推奨を作り直す．
    - コメントの内容は，推奨に採っても，代替に載せても，どちらにもしなくてもよい．採らないときは，なぜ採らないかを理由に書く．
    - どのカードにもない事項を持ち込むコメントは，新しいカードにする．
- ユーザーの提案もカードにし，ユーザーが`OK`して確定とする．AIの同意だけでは確定しない．
    - 理由: AIの同意で確定すると，ユーザーが見ていないものが判断に混ざる．

## 状態
- カードはラウンドをまたいで残り，`OK`か`OPEN`のどちらかの状態を持つ．状態はこの2つだけ．`OPEN`はまだ`OK`されていない状態で，`SKIP`したカードや，コメントを受けて出し直したカードもこれに入る．
- `SAVE`で記録するのは判断だけ．`OPEN`のカードはセッションをまたいで残らない．

## 判断リスト
- 判断リストは，名前と置き場所の決まった1つのファイルではなく，ファイル形式．中身はMarkdownで，ファイル名の末尾は`.decisions.md`．
- 既定の置き場所は設けない．記録しないなら，ファイルなしで動く．
- セッションの中では，ユーザーが指定した判断リストだけを読む．フォルダにある判断リストを探して読むことはしない．
    - 理由: 判断リストの改善では対象も判断リストになる．見つけたファイルを読むと，改善の対象を，従うべき判断として読んでしまう．
- 指定された判断リストは，カードを出す前に読む．

## SAVE
- `SAVE`と指示されたときに記録する．ラウンドループの途中でも記録する．
- そのセッションで`OK`になった判断をすべて，新しい判断リストのファイルに書く．既存のファイルには追記しない．同じセッションで再び`SAVE`したときは，そのセッションのファイルを書き直す．
    - 理由: 判断している段階では，既存の記録への追記なのか更新なのかを決められない．既存のファイルに入れたいときは，判断リストの改善として行う．
- ファイル名の`.decisions.md`の前の部分は，ユーザーが指定する．指定がなければAIが付ける．置き場所も，指定がなければAIが決める．書いたファイルのパスをユーザーに伝える．

### 書き方
- 最初の見出しには，ファイル名の`.decisions.md`の前の部分を書く．
- 次の見出しには，現在の日時をタイムゾーン付きで書く．現在時刻を取得できない環境では日付だけを書き，時刻は推測で書かない．
- 判断だけを並べ，小見出しは置かない．
- IDは，ファイルごとに`D1`から，`OK`になった順に振る．
- 各判断には，本文と理由を書く．
    - 本文には，`OK`になった推奨を書く．問いがないと意味が通らない場合だけ，問いの語を補う．
    - 理由は，カードに書いたものから変えない．
    - 理由だけをラベル付きで書く．それ以外の補いと入れ子の書き方は，カードと同じ．
- 記録の中で他の判断を指すときは，IDに内容を1行添える．
- 語は判断として定める．判断の文面では，定義した語だけを使い，同じ概念を別の語で呼ばない．
- 1つのファイルの中で，同じ説明を2か所に書かず，同じことを別の言い方で書かない．

```
# <名前>

## 2026-11-10 14:30 +09:00
- D1: 設定ファイルはTOMLで書く．
    - 理由:
        - ...
        - ...
- D2: ...
    - 理由: ...
```

## RUN
- ファイルを指定しない`RUN`は，セッション中に`OK`になった判断に従って成果物を作る．先に`SAVE`はしない．
- ファイルを指定した`RUN`は，そのファイルの判断にも従う．
- `OPEN`のカードが残っていても，確かめずに進む．

### 成果物に持ち込まないもの
- このスキルを使っていること，判断リストがあること，判断がどう出されどう決まったかは，成果物に持ち込まない．成果物は，それだけを読んで意味が通るように書き，判断の中身だけを反映する．
    - 判断リストやIDへの参照，スキル名，「合意に基づき」「ユーザーの判断で」のような，決まった経緯を示す書き方がこれにあたる．
    - 成果物は，作業の結果として残るものすべて．コード，コードのコメント，ドキュメント，コミットメッセージ，PRの説明が該当する．含めないのは，判断リストそのもの（改善の対象を除く）と，セッション中の会話だけ．
    - 理由: 判断リストは公開されるとは限らず，読めない読み手には参照の意味がない．IDはファイルごとに振るので，別のファイルでは別の判断を指す．
- 判断の理由を成果物に残したいときは，理由そのものを，成果物の中だけで意味が通る文で書く．書くかどうか，どう書くかは，ふつうのコメントの書き方として判断する．
- このスキルや判断リストを扱うツールを作る作業と，判断リストの改善では，成果物にスキルや判断リストのことを書いてよい．その場合でも，IDや「〜で決めた」のような，作業中に決まった経緯は持ち込まない．

## 判断リストの改善
- このスキルは，記録済みの判断を変える機能を持たない．判断リストの改善は，その判断リストを成果物とするふつうの作業として扱い，カードもふつうに出す．
    - `RUN`で対象の判断リストを書き換え，`SAVE`ではその作業の判断を別の判断リストに記録する．
- 対象の判断リストにある判断を変えるカードでは，変更後の判断を，そのまま記録できる文で推奨に書く．
    - 「〜の文を削るか」のような，文面への操作としては問わない．
    - 問いには，元のIDと内容を1行で書く．理由には，元の判断から何が変わるかを書く．
