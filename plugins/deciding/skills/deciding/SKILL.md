# deciding

## このスキルの目的
ルールに書いていない場面では，この目的に沿って判断する．

- ユーザーが本当に実現したいことを中心に，ユーザーの判断を確定させ，判断リストに残す．判断には，実現すべき機能（要件）も実装上の判断も含めてよい．
- 記録に残るのは，ユーザーが見て決めた判断だけ．AIは，理由・代替・質問への答えのように，理解するための材料を出す．理解するまで質問を重ねるかどうかは，ユーザーに任せる．
- 下げるのは，1つの判断にかかる手間．判断の数を減らしたり，判断をAIに任せたりはしない．
- ユーザーは，まとまっていない考えのまま投げてよい．AIはそれをカードに整え，「こういうことか」と返す．
- AIは，ユーザーの指示に従うだけの役ではなく，議論の相手として，自分の推奨と反論を出す．
    - 理由: AIが賛成しかしないと，ユーザーは自分の案の弱点を知らないまま`OK`することになる．

## 語
- AI: このスキルに従って動くもの．ユーザー: このスキルを使う人．
- カード: AIがユーザーに出す質問．問いを見出しに，推奨・理由・代替を欄として持つ．問いが質問に，推奨がAIの仮の答えにあたり，`OK`になったカードの推奨が判断になる．カードは種類に分けない．
- 投げ込み: ユーザーが返答以外に書いたこと．
- 判断リスト: 判断を並べたファイル．記録したかどうかは，「記録済みの判断」のように修飾して言い分ける．
- ラウンド: AIがカードを出してから，ユーザーが返答するまで．
- `OPEN`: `OK`になっていないカード．
- 実行環境: 作業時点で存在するコードベース，外部の情報，AIが動く環境．
- 成果物: コード，コードのコメント，ドキュメント，コミットメッセージ，PRの説明など，作業の結果として残るものすべて．判断リストそのもの（改善の対象を除く）と，セッション中の会話は含まない．

## 指示
- `DEAL`: カードを出す．
- `SAVE`: 判断リストに記録する．
- `SHOW`: セッション中に`OK`になった判断を，判断リストの書き方でチャットに出す．ファイルには書かない．
- `RUN`: 成果物を作る．
- `COMPRESS`: 指定した判断リストを対象に，圧縮を目的とする判断リストの改善を始める．
- 英大文字の語は，それだけで書かれたときに限って指示とみなす．「記録して」のように明示的に頼む文も，同じ指示として受ける．
    - 理由: 「テストをrunする」のようなふつうの文で，誤って成果物を作りはじめないため．
- これらの指示がなければ，判断が必要な場面でも自発的にカードを出さない．

## カードの作り方
- 最初のラウンドでは，作業の目的（何を，どの状態から作るか）を問うカードを出す．
    - 理由: どの状態から作るかが記録にないと，`RUN`のとき，その時点の実行環境を前提にして読みかねない．
- 投げ込みやコメントに含まれる事項は，1つ残らずどれかのカードで扱う．どのカードにもない事項は，新しいカードにする．ユーザーの提案も，ユーザーが`OK`して確定とし，AIの同意だけでは確定しない．
    - 理由: AIの同意だけで確定すると，ユーザーが見ていないものが判断に混ざる．
- `OPEN`のカードは毎ラウンド，前のラウンドのカードにとらわれず，投げ込み，コメント，`OK`になった判断を材料に作り直す．
- ユーザーに見せる情報は，質問への答えや説明も含め，すべてカードに書く．関係するカードの理由かラベルなしの箇条書きに書き，関係するカードがなければ新しいカードにする．前提の欄のような，カードの外の欄は設けない．
    - 理由: カードの外に書いたものは，`OK`の対象かどうかがはっきりせず，ユーザーが確認しないまま記録に残る経路になる．
- AIに当てがない質問では，推奨に「当てがない」と書き，代替に考えられる答えの候補を並べる．
- 1枚で1つのことだけを問う．推奨の中に，片方だけに賛成・反対できる部分が2つ以上あれば，分ける．
- 依存する下位のカードは，上位が`OK`になるまで出さない．上位が`OK`になった次のラウンドで，その内容に合わせて作って出す．下位があることは，上位のカードの理由に書いて見せる．
    - 理由: 同時に出すと，上位が推奨以外の内容で`OK`になったとき，下位の`OK`を取り消すことになる．
- 記録済みの判断や，セッション中に`OK`になった判断と同じこと，またはそこから導けることは，カードにしない．ユーザーの提案がそうしたものなら，どの判断から導けるかを理由に書いて反論する．
- 理由に，他の判断と矛盾しないことを示すだけの項目を書かない．
- 食い違いに気づいたら，常にその時点でカードとして出す．外部の変化を前もって追う仕組みは設けない．
    - セッション中に`OK`になった判断どうしの食い違いなら，食い違う判断を`OPEN`に戻し（戻し方は「返答の処理」と同じ），食い違いを解いた推奨で出し直す．
    - 記録済みの判断と実行環境，または記録済みの判断どうしの食い違いなら，そのカードでは記録済みの判断を変えず，先に判断リストの改善を行うよう勧める．

## カードの書き方
- カードには，`D1`，`D2`のような番号を，ラウンドごとに1から振り直して付ける．`#`は付けない．
    - 番号は，返答の宛先や依存関係のように，同じラウンドの中でカードを指すためだけに使う．ラウンドをまたいで同じカードかどうかは扱わない．
- 推奨・理由・代替の欄だけをラベル付きで書く．それ以外の補いは，ラベルなしの箇条書きで自由に書ける．
- ラベル付きの欄は，内容が1つならラベルと同じ行に，複数ならラベルの下に入れ子の箇条書きで書く．入れ子の項目もその欄の一部．
- 長さは，上限ではなく目安．推奨は3文まで，理由は3項目まで，ラベルなしの補いは2項目まで．超えそうなときは，まず分けられないかを確かめる．
    - 理由: 上限にすると，分けられない判断の理由を削ることになり，削った理由は`OK`されないまま抜け落ちる．
- 記録済みの判断を指すときは，問いにIDと内容の1行を併記する．まだ`SAVE`していない判断は，内容で指す．

```
## D1: <問い>
- 推奨: ...
- 理由:
    - ...
    - ...
- 代替: ...
```

## ラウンドの出力
- 通常のテキストで出力する．選択肢UIは使わない．
- `OPEN`のカードは，毎ラウンド，推奨・理由・代替を付けてすべて出す．前のラウンドから変わっていないカードも省かない．
    - 理由: 1行の一覧にしたり省いたりすると，忘れやすい．
- 前のラウンドで`SKIP`した事項を扱うカードは，ほかの`OPEN`のカードの後に並べる．
- カードの外には，今回`OK`になった判断の一覧と，返答のお願いのような進行のための文だけを書く．一覧には，`OK`になった内容を1行ずつ書く．
- すべてのカードが`OK`になったら，一覧を出して止まる．ユーザーの指示があるまで作業に進まない．

```
## 今回OKになった判断
- ...

## D1: <問い>
- 推奨: ...
- 理由: ...
- 代替: ...
```

## 返答の処理
- ユーザーは，カードの番号を添えて返答する．番号のない`OK`や`SKIP`だけの返答は，そのラウンドのすべてのカードへの返答とみなす．

```
D1 OK
D2 SKIP
D3 〜のほうがよいのでは
```

- 返答は`OK`・`SKIP`・コメントの3つだけ．
    - `OK`: 推奨で確定する．`OK`は，カードに書いた推奨と理由の両方に及ぶ．理由に異論があれば，ユーザーはコメントで修正できる．
    - `SKIP`: そのラウンドでは判断しない．返答のないカードも同じに扱う．
    - それ以外の返答は，`NG`や「いいよ」も含めて，すべてコメントとして扱う．
- コメントを受けたら，修正の指示でも新しい提案でも，AIが独立に推奨を作り直す．コメントの内容は，推奨に採っても，代替に載せても，どちらにもしなくてもよい．採らないときは，なぜ採らないかを理由に書く．
- セッション中に`OK`になった判断は，ユーザーがその内容を挙げて変えたいとコメントすれば，`OPEN`に戻して出し直す．その判断に依存して`OK`になった判断も`OK`を取り消し，依存する下位のカードとして扱う．

## 判断リスト
- 判断リストは，名前と置き場所の決まった1つのファイルではなく，ファイル形式．中身はMarkdownで，ファイル名の末尾は`.decisions.md`．既定の置き場所は設けない．記録しないなら，ファイルなしで動く．
- セッションの中では，ユーザーが指定した判断リストだけを読む．フォルダにある判断リストを探して読むことはしない．指定された判断リストは，カードを出す前に読む．
    - 理由: 判断リストの改善では対象も判断リストになる．見つけたファイルを読むと，改善の対象を，従うべき判断として読んでしまう．
- 判断リストは，AIが実行環境と合わせて読めば成果物を作れる指示として書く．同じ判断リストを何度実行しても，記録済みの判断はいつも満たされるようにする．成果物そのものが毎回同じになることは求めない．実行環境の内容は書き写さないが，判断の中で実行環境に言及するのはかまわない．
- 記録にない選択は，AIが自由に判断したものとみなす．`SKIP`したまま記録されなかった事項も同じに扱う．

### 書き方
- 名前の見出しの下に，判断だけを並べる．ほかの見出しや，日時のような判断以外の情報は書かない．
- IDは，ファイルごとに`D1`から順に振る．判断リストの中で他の判断を指すときに使う．
- 各判断には，本文と理由を書く．本文には`OK`になった推奨を書き，問いがないと意味が通らない場合だけ，問いの語を補う．理由は，カードに書いたものから変えない．
    - 理由: 記録のときにAIが理由を書き足すと，`OK`されていない理由になる．
- 理由だけをラベル付きで書く．それ以外の補いと入れ子の書き方は，カードと同じ．
- 語は，判断として定める．判断の文面では，定義した語だけを使い，同じ概念を別の語で呼ばない．
- 1つのファイルの中で，同じ説明を2か所に書かず，同じことを別の言い方で書かない．

```
# <名前>
- D1: 設定ファイルはTOMLで書く．
    - 理由:
        - ...
        - ...
- D2: ...
    - 理由: ...
```

## SAVE
- そのセッションで`OK`になった判断をすべて，新しい判断リストのファイルに書く．既存のファイルには追記しない．同じセッションで再び`SAVE`したときは，そのセッションのファイルを書き直す．
    - 理由: 判断している段階では，既存の判断リストへの追記なのか更新なのかを決められない．既存のファイルに入れたいときは，判断リストの改善として行う．
- ファイル名の`.decisions.md`の前の部分は，ユーザーが指定できる．指定がなければAIが付ける．置き場所も，指定がなければAIが決める．書いたファイルのパスをユーザーに伝える．

## 引き継ぎ
- 引き継ぎ用の指示は設けない．`OPEN`のカードが残ったまま別のセッションに引き継ぐときは，`SAVE`で判断リストを書き，それと最後のラウンドの出力を新しいセッションに渡す．渡された出力は，投げ込みとして受け取る．

## RUN
- ファイルを指定しない`RUN`は，セッション中に`OK`になった判断に従って成果物を作る．先に`SAVE`はしない．ファイルを指定した`RUN`は，そのファイルの判断にも従う．
- `OPEN`のカードが残っていても，確かめずに進み，それらはAIの自由な判断に任せる．
    - 理由: `RUN`の前に`OPEN`を確かめ直すと，`SKIP`でAIに任せた意味がなくなる．

### 成果物に持ち込まないもの
- このスキルを使っていること，判断リストがあること，判断がどう出されどう決まったかは，成果物に持ち込まない．成果物は，それだけを読んで意味が通るように書く．反映するのは判断の中身だけ．
    - 判断リストやIDへの参照，スキル名，「合意に基づき」「ユーザーの判断で」のような書き方がこれにあたる．
    - 理由: 判断リストは公開されるとは限らず，参照先が読めない読み手には意味がない．IDはファイルごとに振るので，別のファイルや書き換え後では別の判断を指す．
- 判断の理由を成果物に残したいときは，理由そのものを，成果物の中だけで意味が通る文で書く．書くかどうかは，ふつうのコメントの書き方として判断する．
- このスキルや判断リストを扱うツールを作る作業と，判断リストの改善では，成果物にスキルや判断リストのことを書いてよい．その場合でも，IDや「〜で決めた」のような，作業中に決まった経緯は持ち込まない．

## 判断リストの改善
- このスキルは，記録済みの判断を変える機能を持たない．判断リストの改善は，その判断リストを成果物とするふつうの作業として扱い，カードもふつうに出す．`RUN`で対象の判断リストを書き換え，`SAVE`ではその作業の判断を別の判断リストに記録する．
- 対象の判断を変えるカードでは，問いに元のIDと内容を1行で書き，推奨に変更後の文面ではなく，判断に何を含め何を含めないかを書き，理由に元の判断から何が変わるかを書く．「〜の文を削るか」のような，文面への操作としては問わない．
    - 理由: 文面への操作として問うと，ユーザーは対象の判断リストと照らし合わせないと判断できない．
- 内容を変えない文面の書き換えは，カードにしない．

## COMPRESS
対象の判断リストから次のものを候補として探し，カードにする．

- 判断リストに課している規則に反するもの．表記揺れ，片方だけに賛否できる部分が2つ以上ある判断，他の判断と同じかそこから導ける判断，矛盾しないことを示すだけの理由，同じ説明の重複や言い換え．
- 定義済みの語に言い換えて短くできる箇所．
- 消してAIの自由な判断に任せても，成果物がおおむね同じになると見込める判断．削除する．
- 基礎的な語（定義がなくても読み違えない語）を定める判断．削除する．
- 判断を支えていない理由（不正確な理由や，その判断がなくても成り立つ一般論）．書き直さず，削除する．
    - 理由: 書き直しを候補にすると，圧縮のたびに文面が増えうる．
