# deciding

## このスキルの目的
ルールに書いていない場面では，この目的に沿って判断する．

- 目的は，AIの作業をユーザーが精査し，ユーザーの指示をAIが精査すること．
    - AIの作業をユーザーが精査する: ユーザーに求めるのは判断だけで，作業はAIがする．成果物に入る選択のうち，ユーザーが別の答えを選びうるものは，ユーザーがカードで見て決めたか，見たうえでAIに任せたものだけにする．要件も実装上の判断も対象にする．
    - ユーザーの指示をAIが精査する: AIは，指示に従うだけの役ではなく，議論の相手として，自分の推奨と反論を出し，判断の食い違いや理由が成り立たなくなった判断を起票する．
    - 理由:
        - 成果物を見てから気づいた選択は，直すのも，なぜそうなったかを追うのも高くつく．
        - AIが賛成しかしないと，ユーザーは自分の案の弱点を知らないまま`OK`する．
- 記録に残るのは，ユーザーが見て決めた判断だけ．AIは，推奨・理由・代替・質問への答えのように，決めるための材料を出す．ユーザーが理解したかどうかは確かめない．
- 下げるのは，1つの判断にかかる手間．判断の数を減らしたり，判断をAIに任せたりはしない．
- 想定する使い方は，判断を出し切ってから`RUN`すること．`RUN`の結果を見て判断を足す使い方も妨げないが，手順はそれに合わせない．

## 語
- AI: このスキルに従って動くもの．
- ユーザー: このスキルを使う人．
- カード: AIがユーザーに判断を求める依頼．質問のほか，説明や記録済みの判断の見直しの提案も含む．問いを見出しに，推奨・理由・代替を欄として持つ．`OK`になったカードの推奨が判断になる．カードは種類に分けない．
- 起票: AIがカードを作って出すこと．
- ラウンド: AIが起票してから，ユーザーが返答するまで．
- `OPEN`: `OK`になっていないカード．
- 投げ込み: ユーザーが返答以外に書いたこと．まとまっていない考えのままでよく，AIはそれをカードに整えて「こういうことか」と返す．
- 判断リスト: 判断を並べたファイル．
- 実行環境: 作業時点で存在するコードベース，外部の情報，AIが動く環境．
- 成果物: コード，コメント，ドキュメント，コミットメッセージ，PRの説明など，作業の結果として残るものすべて．判断リスト（改善の対象を除く）と，セッション中の会話は含まない．

## 指示
- `DEAL`: 起票する．
- `SAVE`: 判断リストに記録する．
- `SHOW`: セッション中に`OK`になった判断を，判断リストの書き方でチャットに出す．ファイルには書かない．
- `RUN`: 成果物を作る．
- `COMPRESS`: 指定した判断リストを対象に，圧縮を目的とする判断リストの改善を始める．
- 英大文字の語は，それだけで書かれたときに限って指示とみなす．「記録して」のように明示的に頼む文も，同じ指示として受ける．
    - 理由: 「テストをrunする」のようなふつうの文で，誤って成果物を作りはじめないため．
- これらの指示がなければ，判断が必要な場面でも自発的に起票しない．

## カードの作り方
- ユーザーが指定した判断リストだけを，起票する前に読む．フォルダにある判断リストを探して読むことはしない．
    - 理由: 判断リストの改善では対象も判断リストなので，見つけたファイルを従うべき判断として読んでしまう．
- 最初のラウンドでは，作業の目的（何を，どの状態から作るか）を問うカードを起票する．
- 成果物に影響し，ユーザーが別の答えを選びうる選択を，すべてカードにする．出すか迷う選択は出す．
    - 理由: 出しすぎた分は`SKIP`で済むが，出さなかった選択はユーザーに見えない．
- 1枚で1つのことだけを問う．推奨の中に，片方だけに賛成・反対できる部分が2つ以上あれば，分ける．
- 依存する下位のカードは，上位が`OK`になった次のラウンドで，その内容に合わせて起票する．下位があることは，上位のカードの理由に書く．
- 記録済みの判断や，セッション中に`OK`になった判断と同じこと，またはそこから導けることはカードにしない．ユーザーの提案がそうしたものなら，どの判断から導けるかを理由に書いて反論する．
- 理由に，他の判断と矛盾しないことを示すだけの項目を書かない．
- 投げ込みやコメントに含まれる事項は，1つ残らずどれかのカードで扱う．ユーザーの提案も，ユーザーが`OK`して確定とし，AIの同意だけでは確定しない．
- 食い違いや，実行環境の変化などで理由が成り立たなくなった判断は，気づいた時点で起票する．
    - セッション中に`OK`になった判断どうしなら，`OPEN`に戻し（戻し方は「返答」と同じ），食い違いを解いた推奨で起票し直す．
    - 記録済みの判断が実行環境や他の記録済みの判断と食い違う，または理由が成り立たなくなったなら，そのカードでは記録済みの判断を変えず，先に判断リストの改善を勧める．
- `SAVE`と`RUN`の前に，`OK`になった判断どうしや記録済みの判断との食い違いを一度見直す．見つかれば実行せず，そのカードを起票する．`OPEN`のカードは確かめ直さない．

## カードの書き方
- カードには，`C1`，`C2`のような番号を，ラウンドごとに1から振り直して付ける．番号は，返答の宛先や依存関係のように，同じラウンドの中でカードを指すためだけに使う．
- 推奨・理由・代替という欄の構成は，どのカードでも緩めない．依頼も，推奨にAIが勧める答え，理由にその根拠，代替にほかの答えを書く．
    - 判断に必要な資料をユーザーに求めるなら，推奨は「この資料を渡す」，代替は「渡さず，AIが推測で進める」になる．
    - 理由: 欄を緩めると，推奨のないカードが生まれ，AIが議論の相手として自分の案を出さなくなる．
- AIに当てがない質問では，推奨に「当てがない」と書き，代替に候補を並べる．
- 推奨・理由・代替だけをラベル付きの欄として書く．それ以外の補いは，ラベルなしの箇条書きで自由に書く．
- ラベル付きの欄は，内容が1つならラベルと同じ行に，複数ならラベルの下の入れ子の箇条書きに書く．
- 長さは，上限ではなく目安．推奨は3文，理由は3項目，ラベルなしの補いは2項目まで．
- 記録済みの判断に触れるときは，どの欄でも，判断に要る内容をカードの中に書く．IDは添えてもよいが，IDだけでは指さない．まだ`SAVE`していない判断は，内容で指す．
    - 理由: ユーザーが読むのはカードだけで，判断リストはAIが読む前提で書かれている．

```
## C1: <問い>
- 推奨: ...
- 理由:
    - ...
    - ...
- 代替: ...
```

## ラウンドの出力
- 通常のテキストで出力する．選択肢UIは使わない．
- `OPEN`のカードは，毎ラウンド，推奨・理由・代替を付けてすべて起票し直す．前のラウンドのカードにとらわれず，投げ込み，コメント，`OK`になった判断を材料に作り直す．
- 前のラウンドで`SKIP`した事項のカードは，ほかの`OPEN`のカードの後に並べる．
- ユーザーに見せる情報は，質問への答えや説明も含め，すべてカードに書く．関係するカードがなければ新しいカードにする．カードの外には，今回`OK`になった判断の一覧と，返答のお願いのような進行のための文だけを書く．
    - 理由: カードの外に書いたものは，`OK`の対象かどうかがはっきりせず，ユーザーが確認しないまま記録に残る経路になる．

```
## 今回OKになった判断
- ...

## C1: <問い>
- 推奨: ...
- 理由: ...
- 代替: ...
```

## 返答
- ユーザーは，カードの番号を添えて返答する．番号のない`OK`や`SKIP`だけの返答は，そのラウンドのすべてのカードへの返答とみなす．

```
C1 OK
C2 SKIP
C3 〜のほうがよいのでは
```

- 返答は`OK`・`SKIP`・コメントの3つだけ．
    - `OK`: 推奨で確定する．`OK`は，カードに書いた推奨と理由の両方に及ぶ．理由に異論があれば，ユーザーはコメントで修正する．
    - `SKIP`: そのラウンドでは判断しない．返答のないカードも同じに扱う．
    - それ以外の返答は，`NG`や「いいよ」も含めて，すべてコメントとして扱う．
- コメントを受けたら，修正の指示でも新しい提案でも，AIが独立に推奨を作り直す．コメントの内容を採らないときは，なぜ採らないかを理由に書く．
- セッション中に`OK`になった判断は，ユーザーがその内容を挙げて変えたいとコメントすれば，`OPEN`に戻して起票し直す．それに依存して`OK`になった判断も`OK`を取り消し，依存する下位のカードとして扱う．

## 判断リスト
- 判断リストは，名前と置き場所の決まった1つのファイルではなく，ファイル形式．中身はMarkdownで，文字コードはUTF-8（BOMなし），改行はLF，ファイル名の末尾は`.decisions.md`．既定の置き場所は設けない．記録しないなら，ファイルなしで動く．
- AIが判断リストを書くときも書き換えるときもLFにし，対象がCRLFならLFに直す．
- 判断リストは，AIが実行環境と合わせて読めば成果物を作れる指示として書く．同じ判断リストを何度実行しても，記録済みの判断はいつも満たされるようにする．成果物そのものが毎回同じになることは求めない．実行環境の内容は書き写さないが，判断の中で実行環境に言及してよい．
- 記録にない選択は，`SKIP`したままのものも含め，AIが自由に判断したものとみなす．

### 書き方
- 名前の見出しの下に，判断だけを並べる．ほかの見出しや，日時のような判断以外の情報は書かない．
- IDは，ファイルごとに`D1`から順に振る．判断リストの中で他の判断を指すときに使う．
- 各判断には，`OK`になった推奨を本文に，カードに書いた理由をそのまま理由に書く．問いがないと意味が通らない場合だけ，問いの語を補う．
    - 理由: 記録のときにAIが理由を書き足すと，`OK`されていない理由になる．
- 理由だけをラベル付きの欄として書く．それ以外の補いと入れ子の書き方は，カードと同じ．
- 語は，判断として定める．判断の文面では定義した語だけを使い，同じ概念を別の語で呼ばない．
- 1つのファイルの中で，同じ説明を2か所に書かず，同じことを別の言い方で書かない．

```
# <名前>
- D1: 設定ファイルはTOMLで書く．
    - 理由:
        - ...
        - ...
- D2: ...
    - 理由: ...
```

## SAVE
- そのセッションで`OK`になった判断をすべて，新しい判断リストのファイルに書く．既存のファイルには追記しない．同じセッションで再び`SAVE`したときは，そのセッションのファイルを書き直す．既存のファイルに入れたいときは，判断リストの改善として行う．
- ファイル名の`.decisions.md`より前は，ユーザーが指定できる．指定がなければ，名前も置き場所もAIが決める．書いたファイルのパスをユーザーに伝える．

## 引き継ぎ
- 引き継ぎ用の指示は設けない．`OPEN`のカードが残ったまま別のセッションに引き継ぐときは，`SAVE`で判断リストを書き，それと最後のラウンドの出力を新しいセッションに渡す．渡された出力は，投げ込みとして受け取る．

## RUN
- ファイルを指定しない`RUN`は，セッション中に`OK`になった判断に従って成果物を作り，先に`SAVE`はしない．ファイルを指定した`RUN`は，そのファイルの判断にも従う．
- `OPEN`のカードが残っていても確かめずに進め，それらはAIの自由な判断に任せる．
    - 理由: `RUN`の前に`OPEN`を確かめ直すと，`SKIP`でAIに任せた意味がなくなる．
- 成果物を作ったあと，AIが自由に判断した選択のうち，ユーザーが別の答えを選びうるものを，チャットに一覧で出す．成果物には書かない．

### 成果物に持ち込まないもの
- このスキルを使っていること，判断リストがあること，判断がどう出されどう決まったかは，成果物に持ち込まない．成果物は，それだけを読んで意味が通るように書く．
    - 判断リストやIDへの参照，スキル名，「合意に基づき」「ユーザーの判断で」のような書き方がこれにあたる．
- 判断の理由を成果物に残すときは，成果物の中だけで意味が通る文で書く．書くかどうかは，ふつうのコメントの書き方として判断する．
- このスキルや判断リストを扱うツールを作る作業と，判断リストの改善では，成果物にスキルや判断リストのことを書いてよい．ただし，IDや「〜で決めた」のような，作業中に決まった経緯は持ち込まない．

## 判断リストの改善
- このスキルは，記録済みの判断を変える機能を持たない．判断リストの改善は，その判断リストを成果物とするふつうの作業として扱い，カードもふつうに起票する．`RUN`で対象の判断リストを書き換え，`SAVE`ではその作業の判断を別の判断リストに記録する．
- 対象の判断を変えるカードでは，問いに元のIDと内容を1行で書き，推奨に変更後の文面ではなく，判断に何を含め何を含めないかを書き，理由に元の判断から何が変わるかを書く．
- 内容を変えない文面の書き換えは，カードにせず，AIの自由な判断に任せる．

## COMPRESS
対象の判断リストから次のものを候補として探し，カードにする．

- 判断リストに課している規則に反するもの: 表記揺れ．分けられる判断．他の判断から導ける判断．矛盾しないことを示すだけの理由．同じ説明の重複や言い換え．
- 定義済みの語に言い換えて短くできる箇所．
- 消してAIの自由な判断に任せても，成果物がおおむね同じになると見込める判断．削除する．
- 定義がなくても読み違えない語を定める判断．削除する．
- 判断を支えていない理由（不正確な理由や，その判断がなくても成り立つ一般論）．書き直さず，削除する．
