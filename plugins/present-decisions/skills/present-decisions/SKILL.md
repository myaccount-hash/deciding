# present-decisions

## このスキルの目的
- AIと合意を重ねながら，設計などの判断を固めていく．
- ユーザーは各事項を理解したうえで判断する．
    - 理解するまで質問を重ねてよい．
    - AIは推奨案に理由と代替を添え，質問に答えることで理解を支える．
- ユーザーが合意した事柄と，合意に至っていない事柄（保留）を，DECISIONS.mdに記録する．
    - 記録するのは，ユーザーの判断だけ．
    - 記録にない選択は，AIが自由に判断したものとみなす．
- DECISIONS.mdと実行環境から，要件を満たす成果物を組み立てられるようにする．
    - 実行環境は，作業時点の既存コードベース，外部情報，AIの実行環境を指す．記録しない．
    - 同一のコードではなく，要件を満たす成果物を目指す．

## 起動条件
- ユーザーが「判断事項を提示」などと明示的に指示したときだけ使う．
- 判断が必要な場面でも，指示がなければ自発的に使わない．

## DECISIONS.mdの置き場所
- 既定は，作業対象のリポジトリまたはフォルダのルート．
- ユーザーが置き場所を指定したら，それに従う．
- ファイルがなければ，記録の時点で作成する．記録しないなら，ファイルなしで動く．

## 既存の合意の参照
- DECISIONS.mdがあれば，判断事項を挙げる前に読む．
    - `（圧縮）`の付いた見出しがあれば，最後の`（圧縮）`見出しから末尾までだけを読む．ファイル全体を先に読まない．
        - 例: `grep -n '（圧縮）' DECISIONS.md`で行番号を得て，その行から読む．
- 否定の印が付いた判断は無効とする．
- 未解決の保留と未確定の事項は，最初のラウンドで提示する．
    - 解決の印も更新の印もない保留が，未解決の保留．
- 記録と実行環境の食い違い，記録した判断どうしの食い違いに気づいたら，圧縮かどうかに関係なく，その時点で判断事項として提示する．

## 判断事項
- ユーザーに見せる情報は，すべて判断事項にする．前提の欄は設けない．
    - 要件（目的，対象範囲など）も判断事項にする．
- 実行環境から読み取れることは，判断事項にしない．
    - 既存コード，連携先などの外部の制約は，AIが実行環境から読み取る．
    - 制約への対応をユーザーが選ぶ場合だけ，判断事項にする．
- 判断事項は，1つで1つのことだけを問う．複数のことを問うときは，分ける．
- 他の事項が依存するもの，影響が大きいものを先に並べる．
- 事項間に依存関係があれば明記する．
    - 依存する事項も同時に提示する．
    - 上位の事項が推奨以外で確定したら，下位の事項を同じIDで作り直して再提示する．下位に出ていた了承は無効にする．

## 状態
- 確定: ユーザーが合意した．
- 未確定: ユーザーがまだ指示していない．
- 保留: ユーザーが「保留」と指示した．
    - 保留は，ユーザーの明示的な指示でだけ付ける．AIが勝手に付けない．
- 不要: ユーザーが「不要」と指示した．ユーザーはその事項を判断しない．
- ユーザーができる返答は，「OK」「保留」「不要」「コメント」の4つ．

## 各事項の書き方
- `D1`，`D2`のような通し番号を振る．
    - DECISIONS.mdがあれば，ファイル全体の最大番号と，`（圧縮）`記録の「使用済みの最大ID」のうち，大きいほうの続きから振る．なければ`D1`から振る．
    - ラウンドをまたいで番号を変えない．
    - 新たに追加する事項には続きの番号を振る．
- 各事項に次の項目を書く．
    - 問い: 見出しに書く．
    - 推奨: 推奨案．
    - 理由: 推奨する理由．
    - 代替: 推奨案以外の案．
- ラベルは，上の決まった欄にだけ付ける．それ以外の補い（依存関係など）は，ラベルなしの箇条書きで書ける．
- 判断が特定の外部情報（ファイル，URL，資料）に依存するときは，必要に応じて参照先を書いてよい．理由の中でも，補足の箇条書きでもよい．
- 他の判断事項を参照するときは，IDに加えて参照先の内容を1行で併記する．
    - 例: 「D7（コメントのない事項は再提示する）に従い…」
- 記録済みの判断を否定・変更する事項（圧縮，食い違いの提示など）は，変更後の判断そのもの（本文と理由）を推奨に書く．
    - DECISIONS.mdを見なくても判断できる形にする．「〜の文を削るか」のような，記録の文面への操作としては問わない．
    - 対象の元のIDは，内容を1行で併記して問いに書く．
    - 元の判断から意味がどう変わるかは，理由に書く．
- ユーザーの提案に基づく事項は，推奨をAIが独立に作る．
    - ユーザーの提案は，内容を変えずに代替に載せる．
    - AIの推奨が結果として提案と同じになる場合だけ，提案を推奨にする．

```
## D1: <問い>
- 推奨: ...
- 理由: ...
- 代替: ...
```

## 出力手段
- 通常のテキストで出力する．選択肢UIは使わない．
- カードの外には，今回確定した事項の一覧と，返答のお願いのような進行のための文だけを書く．
- ユーザーは自由記述でコメントする．

## コメントの処理
- 「OK」などの了承は，推奨案で確定とする．
    - 了承は，提示した推奨と理由の両方に及ぶ．
- 提示した代替案の選択は，その案で確定とする．
- 「保留」は，その事項を保留にする．
- 「不要」は，その事項をAIの自由な判断に任せる．以降提示せず，記録もしない．
    - 「その案はやらない」は判断なので，「不要」ではなく，「やらない」案を選ぶコメントで確定する．
- 修正の指示は，修正した内容を推奨にして，同じIDで再提示する．
    - 一部分だけに合意するコメントも，同じように扱う．
    - ユーザーが了承して確定する．
- 新しい提案は，新しいIDの判断事項として提示する．
    - ユーザーが了承して確定する．
- 質問や異論には答え，必要なら修正した推奨案を同じIDで再提示する．
    - 答えや説明は，関係する判断事項の理由か，ラベルなしの箇条書きに書く．関係する事項がなければ，新しい判断事項にする．
- コメントのない事項は未確定のまま，次のラウンドで再提示する．
- AIの同意だけでは確定しない．

## 2ラウンド目以降の出力
- そのラウンドで新たに確定した事項，保留，未確定事項を出力する．
    - 新たに確定した事項は，コメントの解釈を確認できるよう確定内容を1行で示す．
    - 保留は，毎ラウンド，他の事項と同じ形（推奨・理由・代替付き）で提示する．
- 確定済みの事項は再掲しない．

```
## 今回確定した事項
- D2: ...

## D1: <問い>
- 推奨: ...
- 理由: ...
- 代替: ...
```

## 全事項確定後
- 確定事項と保留の全一覧を出力して止まる．
- DECISIONS.mdに記録していない合意があれば，一覧の最後に「未記録」と1行添える．
- ユーザーの指示があるまで作業に進まない．

## 実装の依頼
- 未確定の事項が残っていれば，進む前に，確定か保留か不要かを指示してもらう．
- 未記録の合意があれば，実装の前にDECISIONS.mdに記録する．
- 保留は，最後に提示した推奨で実装する．
- 未確定の事項は，実装の根拠にしない．
- AIが実装中に自由に判断したことは，記録しない．

## DECISIONS.mdへの記録
- ユーザーが「記録」と指示したとき，または実装を依頼されたときに追記する．
    - 全事項が確定する前でも，「記録」の指示があれば記録する．
- 「記録」の指示1回につき，見出し1つのセクションにする．見出しに現在の日時をタイムゾーン付きで書く．
    - 現在時刻を取得できない環境では，日付だけを書く．時刻は推測で書かない．
- 記録には，確定事項，保留，未確定を書く．前提の欄は設けない．
    - 確定事項には，IDを付け，理由を書く．理由は提示したものから変えない．
    - 保留には，IDと`（保留）`を付け，推奨，理由，代替を書く．
    - 未確定には，IDを付け，推奨，理由，代替を書く．次のセッションの最初のラウンドで提示する．
    - 決まった欄以外の補いは，ラベルなしの箇条書きで書ける．
    - 不要とした事項，取り下げた事項は記録しない．
    - 圧縮で旧記録を残すか削除するかの判断は記録しない．
- 過去の判断を否定する確定事項には，否定対象のIDと内容を1行で併記する．
- 保留を解決する確定事項は，新しいIDで書き，解決する保留のIDと内容を1行で併記する．
- 保留の推奨が変わったら，新しい記録に同じIDで保留を書き直す．
- 未確定の事項が確定したら，新しい記録に同じIDで書く．元の未確定には印を付けない．
- 既存の記録は書き換えない．例外として，否定された判断，解決された保留，更新された保留の下に，印を1行追記する．また，圧縮で旧記録を削除する場合を除く．
- 否定した判断，解決した保留，更新した保留をユーザーに報告する．

```
## 2026-11-10 14:30 +09:00
### 確定事項
- D12: ...
    - 理由: ...
    - D5（設定ファイルはYAMLで書く）を否定する．
- D13: ...
    - 理由: ...
    - D9（○○の扱い）の保留を解決する．

### 保留
- D14（保留）: <問い>
    - 推奨: ...
    - 理由: ...
    - 代替: ...

### 未確定
- D15: <問い>
    - 推奨: ...
    - 理由: ...
    - 代替: ...
```

否定された判断には次のように印を付ける．

```
- D5: 設定ファイルはYAMLで書く．
    - 理由: ...
    - → D12で否定（2026-11-10 14:30 +09:00）
```

解決された保留には次のように印を付ける．

```
- D9（保留）: <問い>
    - 推奨: ...
    - 理由: ...
    - 代替: ...
    - → D13で解決（2026-11-10 14:30 +09:00）
```

推奨が変わった保留には次のように印を付け，新しい記録に同じIDで書き直す．

```
- D14（保留）: <問い>
    - 推奨: ...
    - 理由: ...
    - 代替: ...
    - → 2026-11-12 09:00 +09:00の記録で更新
```

## 圧縮
- ユーザーが「圧縮」と指示したときだけ実行する．
- AIに選ぶ余地がある操作だけを，判断事項としてユーザーに提示する．記録済みの合意から一通りに決まる操作は，提示せずに行う．
- 手順:
    1. 有効な事項を集める．否定された判断，解決済みの保留，更新前の保留を除く．未確定の事項は含める．
        - 残す事項の中にある，除いた事項への言及（否定の併記など）も消す．
    2. 統合や言い換えをするか，それを提示するかは，上の方針に沿ってAIがその都度判断する．
    3. 提示が要る操作（統合，有効な事項の削除，文面の変更など）を判断事項として提示し，通常のラウンドで確定させる．
        - 新しい番号を振り，問いに対象の元のIDを書く．
        - 操作ではなく，変更後の判断そのものを推奨に書く（「各事項の書き方」の記録済みの判断を変える事項を参照）．
    4. 旧記録を「残す」か「削除する」かを，判断事項として提示する．
    5. 3で確定した事項を，圧縮の前に通常の記録として書く．
        - 元の事項を否定する新しい判断として書く．IDは提示したときの番号を使う．
        - 意味を確かめただけで文面が変わらなかった事項は，記録しない．
        - 4の判断は記録しない．
    6. 5の記録を含めて，1の手順で有効な事項を集め直し，圧縮した記録を書く．
- IDは元のIDを維持する．統合した事項は，5で振った新しいIDになる．圧縮した記録には，統合元のIDを書かない．
- 圧縮した記録の見出しには，日時の後ろに`（圧縮）`を付ける．
- 見出しのすぐ下に，圧縮の範囲と，その時点で使った最大のIDを書く．
- 旧記録を残す場合: 旧記録の後ろに，圧縮した記録を追記する．以降は，最後の`（圧縮）`記録から末尾までだけを読む．
- 旧記録を削除する場合: 旧記録を消し，圧縮した記録だけを残す．

```
## 2026-11-20 10:00 +09:00（圧縮）
- 2026-11-14 15:43 +09:00までの記録を圧縮した．
- 使用済みの最大ID: D60

### 確定事項
- D2: ...
    - 理由: ...
- D60: ...
    - 理由: ...

### 保留
- D14（保留）: ...
```
