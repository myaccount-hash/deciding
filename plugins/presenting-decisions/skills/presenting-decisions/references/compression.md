# DECISIONS.mdの圧縮

- ユーザーが「圧縮」と指示したときだけ実行する．
- 圧縮前の記録は，棄却されたものとみなす．圧縮前の情報はどこにも残さない．
    - 圧縮で提示する事項にも，圧縮した記録にも，圧縮前の事項への言及や痕跡を書かない．元のID，元の判断からの変化，まとめた理由がこれにあたる．
    - 理由: 圧縮した記録を，それだけで完結した合意の一覧にするため．痕跡を残すと，次の圧縮でも消すべき対象として残り続ける．

## 手順
1. 有効な事項を集める．否定された判断，解決済みの保留，更新前の保留を除く．未確定の事項は含める．
2. 解釈が必要になるもの，判断が必要になるものを，新しい判断事項として提示し，通常のラウンドで確定させる．
    - 記録した合意から一通りに決まる整理は，提示せずにAIが行う．
    - 1つの判断に複数の操作が伴っても，判断事項は1つにする．
    - 問いには，何を決めるかを書く．元のIDも，「まとめる」「消す」のような操作も書かない．
    - 推奨と理由には，判断そのものを書く．
    - 自明なものや，実行環境から読み取れるものなど，消したほうがよいと考える事項は，消すことを判断事項として提示してよい．問いには何を記録に残すかを書き，推奨には「記録しない」とその理由を書く．
3. 1で集めた事項と2で確定した事項から，圧縮した記録を作る．
    - 2で確定した事項は，圧縮した記録に直接書く．圧縮の前に通常の記録としては書かない．
    - 事項には`D1`から通し番号を振り直す．
4. DECISIONS.mdを，圧縮した記録で上書きする．

## 書式
- 圧縮した記録の見出しは，通常の記録と同じく日時だけにする．`（圧縮）`の印，圧縮の範囲，使用済みの最大IDは書かない．

```
## 2026-11-20 10:00 +09:00
### 確定事項
- D1: ...
    - 理由: ...
- D2: ...
    - 理由: ...

### 保留
- D3（保留）: ...
```
